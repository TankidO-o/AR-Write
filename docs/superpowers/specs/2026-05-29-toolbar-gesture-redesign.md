# 工具栏 UI 改版 & 手势精简 & 自定义手势扩展 设计文档

> 日期: 2026-05-29 | 状态: 待实现

## 概述

当前系统存在三个问题：
1. **手势太多**（5 个内置手势），用户记忆负担重
2. **工具栏 UI 简陋**，底部单行排列，无分组无反馈，与手势交互场景不匹配
3. **自定义手势动作太少**（仅 4 种），限制创作灵活性

本次改版目标：
- 手势精简到 2 个核心姿势，用时长/状态区分不同操作
- 工具栏重构为左侧纵向 5 区卡片式布局
- 自定义手势动作从 4 种扩展到 8 种
- 引入三层视觉反馈体系

## 一、手势精简：5 → 2 核心手势

### 1.1 手势映射表

| 手势 | 操作 | 触发条件 | 备注 |
|---|---|---|---|
| 🤏 拇指+食指尖捏合 | **书写** | 即时开始 | 笔尖跟随拇指食指中点 |
| 🖐️ 五指完全伸直 | **区域擦除** | 即时开始 | 手掌中心为擦除锚点 |
| 🖐️→✋ 擦除手势保持 | **清空画布** | 保持 1.5s + 手部位置稳定 | 见 1.2 稳定判定逻辑 |
| 🤏→张开 快速脉冲 | **撤销** | 快速捏合再张开（< 300ms） | 类似"捏一下就回退" |

**移除的内置手势：**
- ❌ `switch` (拇指中指捏合切换颜色) — 改为自定义手势 + 侧边栏
- ❌ 独立 `clear` (握拳清空) — 合并到擦除手势的长按
- ❌ 独立 `undo` (比耶撤销) — 改为捏合快速脉冲

### 1.2 清空画布的「手部稳定」判定

防止正常擦除时误触清空：

```
擦除手势激活 → 记录手掌中心位置 P₀
每帧计算位移: Δ = |P_current - P₀|
如果 Δ < STABLE_THRESHOLD (约 15px 画布空间) → 累积稳定时间
如果 Δ > STABLE_THRESHOLD → 重置计时，更新 P₀
稳定时间达到 1.5s → 触发清空
```

参数：
- `STABLE_THRESHOLD`: 15px（画布坐标，相对于 1920×1080 归一化）
- `CLEAR_HOLD_MS`: 1500ms
- 视觉反馈：L2 环形进度条仅在计时开始后显示，重置时回缩

### 1.3 撤销的「快速脉冲」判定

```
捏合手势激活 (WRITE) → 记录时间 T_start
如果在 T_start + 300ms 内手势转为 IDLE → 判定为「快速脉冲」
→ 触发 undo()
→ 进入 debounce 避免连续误触
```

参数：
- `UNDO_PULSE_MAX_MS`: 300ms
- `UNDO_DEADZONE_MS`: 500ms（触发后冷却）
- **冲突处理**：如果捏合期间产生了笔画点（`beginStroke` 已被调用），即使 < 300ms 也不触发撤销。撤销脉冲仅在「捏合→松开→从未落笔」时生效。

### 3.3 Redo 栈设计

```
DrawLayer 新增:
  this.redoStack = []  // 被撤销的笔画

undo(): 弹出最后一个未擦除笔画 → push 到 redoStack
redo(): 弹出 redoStack 最后一个 → 恢复笔画 → push 回 strokes
clearAll(): 同时清空 redoStack
beginStroke(): 清空 redoStack（新笔画使 redo 历史失效）
```

## 四、三层视觉反馈

### 4.1 架构

新增独立模块 `frontend/js/feedback-layer.js`，统一管理三层反馈 DOM 元素。

```
┌────────────────────────────┐
│  L3 Toast (顶部中央)        │  ← 瞬态，1s 自动消失
│  ⚡ 笔刷大小 → M            │
├────────────────────────────┤
│                            │
│        L2 Progress         │  ← 长按操作时显示
│        (画布中央)           │
│      ⟳ 进度环 66%          │
│                            │
├────────────────────────────┤
│              L1 Status ──→ │  ← 右上角，手势激活期间持续显示
│              🤏 书写 · 4px │
└────────────────────────────┘
```

### 4.2 各层设计

**L1 — GestureStatus（持久）**
- 位置：画布右上角，距边缘 12px
- 外观：半透明深色背景卡片，圆角 10px
- 内容：`{icon} {手势名} · {颜色色块} · {N}px` 或 `{icon} {手势名} · 擦除 {N}px`
- 动画：手势切换时做 `scale(1.05)` → `scale(1)` 弹跳 200ms
- 手势离开 (IDLE) 时 300ms 淡出消失

**L2 — HoldProgress（过渡）**
- 位置：画布正中央
- 外观：SVG 环形进度条，外径 80px，线宽 4px
- 颜色：清空=#ff4444，撤销=#cc66ff
- 动画：进度从 0° → 360° 顺时针填充
- 显示条件：手势被识别 + 位置稳定判定通过后才出现
- 取消时：300ms 回缩动画

**L3 — ActionToast（瞬态）**
- 位置：画布顶部中央，距顶部 16px
- 外观：圆角胶囊，半透明深色背景，icon + 文字
- 持续时间：动作确认类 1s，颜色切换类 0.8s
- 动画：`translateY(-10px)` + `opacity: 0` → `translateY(0)` + `opacity: 1` 淡入，1s 后反向淡出

### 4.3 文件

- 新增 `frontend/js/feedback-layer.js`
- `index.html` 移除旧的 `.gf-toast`（由 L3 替代）
- `gesture-feedback.js` 可移除或重构并入新模块

## 五、区域擦除算法

### 5.1 当前问题

`DrawLayer.eraseAt()` 是「整线擦除」：只要擦除圆碰到笔画上的任意一个点，整根线就标记为 erased。

### 5.2 改进方案：片段擦除

```
遍历所有未擦除笔画:
  对于每个笔画 stoke:
    遍历 stoke 的所有点:
      找出被擦除圆覆盖的连续点段
      将笔画拆分为:
        - 未被覆盖的片段（保留，成为新的独立笔画）
        - 被覆盖的片段（丢弃）
```

简化实现（避免复杂拆分）：
```
遍历所有未擦除笔画:
  遍历 stoke 的每个点:
    如果点在擦除圆内 → 标记该点为 "erased"
  移除所有被标记的点
  将剩余点重新连接:
    - 连续段 > 2 个点 → 保留为独立笔画
    - 连续段 ≤ 2 个点 → 丢弃（碎屑清理）
```

### 5.3 性能考虑

- 擦除操作频率高（每帧可能调用），需优化
- 使用空间索引（bbox 快速剔除）
- 每帧最多处理当前悬停位置附近的笔画
- 大量笔画时考虑批量重绘而非逐笔画重绘

## 七、测试要点

1. **手势切换流畅性**：书写⇔擦除频繁切换，确认 debounce 不卡顿
2. **清空画布防误触**：擦除时手掌移动 ≠ 触发清空；手掌静止 = 1.5s 后清空
3. **快速脉冲撤销**：正常书写起笔不应误触发撤销
4. **区域擦除效果**：只擦圆圈内片段，不删整根线
5. **Redo 栈正确性**：撤销后重做应恢复；新笔画应清空 redo 栈
6. **自定义手势新动作**：setBrushSize / setEraserSize / redo / setBackground 全部可录制和触发
7. **侧边栏响应式**：小屏幕下宽度自适应，不溢出
