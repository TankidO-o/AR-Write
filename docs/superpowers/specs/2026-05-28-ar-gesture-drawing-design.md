# AR 手势书写交互系统 — 项目方案书

## 一、项目概述

### 1.1 项目目标

构建一个基于计算机视觉的交互式增强现实（AR）演示系统。用户通过电脑摄像头进行隔空手势操作，在实时视频画面上叠加书写笔迹、擦除内容，并控制画笔参数，实现无需物理输入设备的自然交互体验。

### 1.2 核心功能

- 隔空书写：拇指与食指捏合，在摄像头画面上追踪指尖轨迹并实时绘制笔迹
- 手势擦除：五指张开，以手掌中心为圆心擦除附近已绘制笔迹
- 颜色切换：食指伸出在空间中画小圈，循环切换预设画笔颜色
- 清空画布：握拳保持 1 秒，清空全部笔迹（含视觉倒计时反馈）
- 撤销操作：食指与小指伸出（摇滚手势），撤销最近一笔
- 工具栏控制：提供颜色选取器、笔刷大小滑块、撤销/清空按钮、截图保存功能，与手势操作共享同一状态

### 1.3 部署模型

系统采用纯本地部署架构——Python 后端与浏览器前端运行于同一台设备，视频帧仅在本地内存中处理，不会传输至外部网络。

## 二、技术选型

### 2.1 总体架构

Web 前端 + Python 后端跨平台方案。后端负责摄像头采集与手部关键点检测，前端负责手势识别判定、Canvas 渲染与 UI 交互。

### 2.2 后端技术栈

| 组件 | 技术 | 职责 |
|------|------|------|
| 摄像头采集 | OpenCV (cv2.VideoCapture) | 读取摄像头帧，640×480 |
| 手部检测 | MediaPipe Hands | 提取 21 点手部关键点归一化坐标 + 左右手标签 |
| Web 框架 | FastAPI | 提供 WebSocket 端点 |
| 通信协议 | WebSocket (ws://localhost) | 每帧推送关键点数组至前端 |

### 2.3 前端技术栈

| 组件 | 技术 | 职责 |
|------|------|------|
| 视频预览 | getUserMedia + HTMLVideoElement | 显示本地摄像头画面 |
| 笔迹渲染 | HTML5 Canvas 2D (分层) | 活跃笔画与历史笔画分离渲染 |
| 通信 | 浏览器 WebSocket API | 接收关键点数据，指数退避重连 |
| 轨迹平滑 | One-Euro Filter | 消除关键点抖动 |
| 手势识别 | 规则引擎（纯前端 JS） | 基于关键点几何关系判定手势 |

### 2.4 选型理由

MediaPipe Hands 成熟稳定，在 CPU 模式下即可达到 10-25ms/帧的检测速度，社区资源丰富。手势规则引擎基于指尖距离、手指伸展状态等直观几何特征，判定逻辑可解释、可调参，适合原型阶段快速迭代。Canvas 2D API 通用性好，分层渲染策略可控制重绘开销。WebSocket 全双工低延迟，满足实时交互需求。

## 三、系统架构

### 3.1 管道结构

```
摄像头 → OpenCV 读帧 → MediaPipe Hands 检测 → WebSocket 推送关键点
                                                      ↓
浏览器视频预览 ← getUserMedia         前端手势规则引擎 + One-Euro 平滑
        ↓                                        ↓
   Canvas 叠加层 ←←←←←← 手势状态机（确认手势 → 动作调度）
```

### 3.2 后端模块

- camera.py：封装 OpenCV VideoCapture，单例模式。提供 start / stop / read_frame 接口。
- hand_detector.py：封装 MediaPipe Hands。输入 RGB 帧，输出最多两只手的 21 个关键点（x, y, z 归一化坐标）及左右手标签。仅追踪最先检测到的那只手，锁定其 handedness 标签，忽略后续出现的其他手。
- server.py：FastAPI 应用，单一路由 /ws。主循环为读帧 → 检测 → 序列化关键点 → WebSocket 发送。发送前丢弃上一帧未确认的待发送缓冲（最新帧优先策略）。关键点坐标截断至 4 位小数以缩减报文体积。

### 3.3 前端模块

- video-layer.js：通过 getUserMedia 获取本地摄像头流，渲染到隐藏的 video 元素。视频使用 CSS object-fit: contain 等比缩放。
- ws-client.js：WebSocket 连接管理。断线后指数退避重连（1s → 2s → 4s → ... → 最大 30s）。达到最大重试间隔后显示连接断开提示，提供手动重连按钮。
- gesture-state-machine.js：所有手势判定逻辑集中于此。包含 5 个独立判定函数 + 防抖 + 死区时间 + 优先级解析。输出已确认的手势事件给下游模块。详细设计见第四章。
- draw-layer.js：Canvas 2D 绘制层，独立 Canvas 元素绝对定位叠加在视频上方。采用分层渲染策略：活跃笔画使用独立 offscreen canvas，历史笔画使用静态 canvas，新增点时仅重绘活跃层，封笔时合并至历史层。笔画历史数组 strokes[] 中每笔记录颜色、线宽、坐标点序列、是否已擦除（逻辑删除）。
- toolbar.js：UI 控制面板。提供预设 6 色选取器 + 自定义颜色、笔刷大小滑块、撤销/清空按钮、截图保存按钮。手势操作与按钮操作共享 draw-layer 状态，同效。

## 四、手势设计

### 4.1 手势定义表

| 手势 | 判定规则 | 触发动作 | 优先级 |
|------|---------|---------|--------|
| Idle（空闲） | 无手检测或连续 3 帧无匹配手势 | 无操作，系统默认状态 | — |
| Write（书写） | 拇指与食指指尖捏合（两指尖欧氏距离 < 阈值），其余三指收拢 | 追踪两指尖中点坐标，在 Canvas 上绘制连续线条 | 最高 |
| Clear（清空） | 五指全部收拢（握拳），保持 1 秒 | 清空全部笔迹 | 高 |
| Erase（擦除） | 五指全部伸展张开，手掌面向摄像头 | 以手掌中心为圆心、默认半径内擦除笔迹 | 中 |
| Switch（切换颜色） | 食指为唯一伸出指，且食指指尖在空间中累计画圈角位移 ≥ 180° | 循环切换至下一预设颜色 | 低 |
| Undo（撤销） | 食指与小指伸展，中指与无名指收拢（摇滚手势） | 撤销最近一笔 | 最低 |

### 4.2 优先级与互斥规则

每个关键点帧中，按优先级从高到低依次评估各手势判定函数。一旦某手势条件满足并被防抖确认，同一帧内不再评估更低优先级的手势。

Write 判定优先级最高——一旦被识别为 Write，不评估 Switch 和 Erase。Switch 仅在食指为唯一伸出指（其余四指收拢）时才进入评估，避免书写时微弧线误触发。Switch 触发阈值降至半圈（180°），缩短操作延迟，前端提供旋转进度环视觉反馈。

手势切换后进入 200ms 死区时间，期间忽略所有新手势判定，消除手势过渡帧导致的误判。

### 4.3 防抖机制

连续 N 帧（默认 N=5，约 200-250ms）判定结果一致才确认手势切换。Idle 的进入条件较宽松——仅需连续 3 帧无匹配手势即可退回 Idle。

握拳清空采用混合计时：一旦手势被防抖确认为握拳，前端启动独立 1 秒倒计时器，在 UI 上显示圆环进度动画。若 1 秒内手势发生变化（手指数目变化），取消计时。

### 4.4 关键几何计算

- 捏合距离：拇指指尖（TIP_4）与食指指尖（TIP_8）的欧氏距离
- 手指伸展判定：指尖 y 坐标 < 对应 PIP 关节 y 坐标（手背朝上时）
- 手掌中心：手腕（WRIST）与中指掌指关节（MCP_12）连线的中点
- 画圈角度累积：逐帧计算食指指尖位移向量，累积方向变化角度的绝对值

## 五、坐标系统

### 5.1 坐标映射

Canvas 尺寸与 video 元素实际渲染尺寸一致（CSS object-fit: contain 后的实际像素区域）。MediaPipe 输出的归一化坐标（0~1）到 Canvas 像素坐标的映射公式：

```
canvasX = normalizedX × canvasWidth
canvasY = normalizedY × canvasHeight
```

### 5.2 轨迹平滑

对书写和擦除模式下涉及的指尖/掌中心坐标点，独立应用 One-Euro Filter。该滤波器自适应调整截止频率：高速运动时放宽平滑以保持响应性，低速运动时收紧平滑以抑制抖动。

参数配置：β = 0.007（速度系数），f_c_min = 1.0 Hz（最小截止频率）。Idle / Switch / Undo 模式下的关键点不做平滑处理，透传原始坐标。

## 六、Canvas 渲染方案

### 6.1 分层 Canvas 架构

共使用 3 个 Canvas 层，自底向上依次为：

- 底层（历史层）：存储已封笔的历史笔画，仅在新笔封笔合并时全量重绘
- 中层（活跃层）：渲染当前正在书写的笔画，每新增一个点增量绘制（仅绘制最近的一个线段，不清空全层）
- 顶层（光标层）：渲染手势光标指示器（捏合位置的光点、手掌擦除区域的半透明圆形）

### 6.2 笔画数据结构

```javascript
strokes: [{
  id: string,           // 唯一标识
  color: string,        // CSS 颜色
  lineWidth: number,    // 线宽（像素）
  points: [{x, y}],     // 坐标点序列
  erased: boolean,      // 逻辑删除标记
  bbox: {x, y, w, h}    // 包围盒（用于脏矩形与擦除碰撞检测）
}]
```

### 6.3 擦除碰撞检测

前端 receive 手掌中心坐标后，遍历 strokes[] 中非 erased 笔画的包围盒，对包围盒与擦除圆重叠的笔画逐点检测各线段到手掌中心的距离，距离小于擦除半径的点段标记为 erased = true。

### 6.4 撤销与清空

- 撤销：将 strokes[] 中最后一条非 erased 笔画标记为 erased = true，触发历史层全量重绘
- 清空：strokes[] 中所有条目标记为 erased = true，触发全量重绘

## 七、WebSocket 通信协议

### 7.1 消息格式（服务端→客户端）

```json
{
  "timestamp": 1716912000.123,
  "fps": 25.3,
  "hand": {
    "handedness": "Right",
    "keypoints": [
      {"id": 0, "x": 0.5123, "y": 0.6451, "z": -0.0231},
      ...
    ],
    "palm_center": {"x": 0.5123, "y": 0.5500}
  }
}
```

### 7.2 连接管理

- 心跳：前端每 5 秒发送 ping 帧，后端回复 pong。10 秒无响应判定断开。
- 重连：指数退避，初始 1s，每次翻倍，最大 30s。连接失败 10 次后显示断开提示。

## 八、性能预算

### 8.1 各环节耗时估算（单帧）

| 环节 | 估算耗时 | 备注 |
|------|---------|------|
| OpenCV 读帧 | 2-5ms | 640×480, USB 摄像头 |
| MediaPipe Hands 检测 | 10-25ms | 关键耗时，CPU 模式 |
| JSON 序列化 + WS 发送 | 0.5-1ms | 浮点截断至 4 位小数 |
| 前端手势判定 + 平滑 | 0.2-0.5ms | 纯数值计算 |
| Canvas 分层重绘 | 1-3ms | 分层策略，仅重绘变化区域 |
| 合计 | 14-35ms | 理论可达 28-60 FPS |

### 8.2 降级策略

- 级别 1（FPS < 15）：输入分辨率降至 320×240，MediaPipe 耗时约减半
- 级别 2（FPS < 10）：关闭前端视频预览（video 元素隐藏），仅显示 Canvas 纯色背景
- 级别 3（持续卡顿）：在 UI 上显示性能警告指示器，建议用户降低环境光照复杂度

### 8.3 后端最新帧优先

每帧开始前，检查 WebSocket 发送缓冲区。若上一帧数据尚未被 TCP 确认发送，则丢弃该帧，直接发送当前帧最新数据，避免背压积压导致的"惯性漂移"。

## 九、风险分析与应对

| 风险 | 等级 | 应对措施 |
|------|------|---------|
| MediaPipe 关键点抖动导致书写不流畅 | 高 | One-Euro Filter 实时平滑，自适应截止频率 |
| Write / Switch 手势误判 | 高 | Switch 仅食指独伸时评估；优先级链 + 死区时间 |
| 低配机器 FPS 不足 | 中 | 三级降级策略，逐级削减负载 |
| 捏合临界值附近笔画断裂 | 中 | 捏合判定加入迟滞（hysteresis）：触发阈值与解除阈值不同，相差 20% |
| 手部进出画面状态混乱 | 低 | 手消失后自动回退至 Idle，重新出现时不经防抖直接回到 Idle |
| 多手干扰 | 低 | 锁定最先检测到的手及其 handedness 标签 |

## 十、开发路线图

### Phase 1：基础管线（摄像头→检测→预览）

- OpenCV 摄像头采集
- MediaPipe Hands 关键点提取
- WebSocket 推送原始关键点到前端
- 前端接收并叠加显示关键点骨架

### Phase 2：手势识别引擎

- 实现 5 个判定函数
- 实现防抖、死区时间、优先级链
- 实现 Idle 状态与状态机完整逻辑
- 实现 One-Euro Filter 轨迹平滑

### Phase 3：Canvas 绘制与擦除

- 分层 Canvas 架构搭建
- 笔画数据结构与历史管理
- 书写笔迹实时渲染
- 擦除碰撞检测与逻辑删除
- 撤销/清空功能

### Phase 4：UI 与完整体验

- 工具栏 UI（颜色、笔刷、按钮）
- 手势视觉反馈（光标、进度环、倒计时）
- 截图保存（Canvas.toDataURL → download）
- 性能监控与降级触发

### Phase 5：打磨与测试

- 多光照条件测试
- 不同手型适配
- FPS 稳定性调优
- 文档完善
